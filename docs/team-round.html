Agents in isolated Daytona sandboxes were told to ship one project per team. They elected integrators, agreed interfaces over chat, and shipped code to each other across sandbox boundaries. Two of them also discovered, mid-round, that they were overwriting each other.

What changed

In the previous round, ten agents on three teams produced ten separate web apps. Each was judged as a team, but every agent had quietly built its own page. Teams existed on the scoreboard and nowhere else.

Two mechanisms did it. share_file copies a file from one agent's sandbox into a teammate's, and a per-team submit lock accepts only the first submission from each team and redirects the rest. Neither forces cooperation; they make it the path of least resistance.

They negotiated an interface before writing code

No prompt told them to appoint an integrator or define a namespace. Both teams arrived at the same structure within ninety seconds of the build phase opening.

Conventions for your snippet: wrap everything in a Drift.timer namespace (avoid globals)… rex → juno, t+57s, after claiming integration for team-1
Plan: iris builds core overlap grid + integrates/submits final index.html… otto → vera, t+49s, team-2

Work then split along those lines: ada took stats and keyboard shortcuts, juno took the timer engine and a completion chime, vera took visual design. Each built in their own sandbox and delivered.

Two agents found a race condition in their own collaboration

Delivery wrote to the same path in the recipient's sandbox. Nothing warned anyone. Both teams hit it, and both noticed unprompted.

My file got overwritten by ada's share. Restoring my tested version immediately. rex, t+221s, team-1's integrator
Heads up: the file that landed in my sandbox via your share_file is byte-identical to the one I sent you… otto → iris, t+186s
Ah, mystery solved: your share landed in my sandbox right before I called share_file to you, so I unknowingly sent your own file back. iris → otto, t+207s, diagnosing it correctly

This is a genuine distributed-systems hazard, discovered by the agents rather than by us, and recovered from inside the round. It is also the clearest argument for the whole exercise: the failure mode only appears when independent agents share mutable state under time pressure, which no single-agent benchmark reproduces.

Scoreboard

Known issues

Fixed after this round

share_file overwrote the recipient's file at the same path

Deliveries now land under incoming/<sender>/<path> and never touch the recipient's own files. The integrator merges deliberately instead of discovering a tested file was replaced.
